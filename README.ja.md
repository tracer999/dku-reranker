# DKU-reranker-v1

[한국어](README.md) | [English](README.en.md) | **日本語** | [中文](README.zh.md)

**韓国語 PDF 文書を対象とする検索拡張生成（RAG）向けのリランカー（reranker）です。**
小規模言語モデル（SLM）に渡す根拠チャンクの順位を並べ替え、答えを含むチャンクが入力の先頭に来るようにします。

公開モデル [`BAAI/bge-reranker-v2-m3`](https://huggingface.co/BAAI/bge-reranker-v2-m3) の
本体重みは**凍結**したまま、韓国語の公的機関 PDF 報告書の**正解根拠ラベル**で LoRA アダプタのみを学習しました。
アダプタは 8.9MB で、ベースモデルは利用側が公開リポジトリから取得します。

| 項目 | 内容 |
|---|---|
| 使う場所 | RAG パイプラインの**検索後・生成前** |
| 役割 | 質問とチャンクを対でスコア付けし、**順位を付け直す** |
| ベースモデル | `BAAI/bge-reranker-v2-m3`（本体凍結・LoRA アダプタのみ学習） |
| 学習データ | 韓国語の公的機関 PDF 報告書 264 問・4 機関 |
| 評価 | `google/gemma-4-E2B-it` で 81 問 — 公開 BGE の 17 に対し **58** |
| サイズ | アダプタ 8.9MB（`r=8`） |
| ライセンス | Apache-2.0 |

`DKU` は檀国大学校（Dankook University）を指します。

---

## 1. 何をするか

検索で取得したチャンクのうち、**答えの根拠となるチャンクを先頭へ引き上げます。**

```
質問 + [チャンク1, チャンク2, …, チャンクN]
        ↓  (質問, チャンク) の組ごとにスコアを 1 つ
        ↓  スコアの降順に並べ替え
質問 + [正解根拠, …, …]      ← 生成モデルにはこの順で渡す
```

小規模言語モデルは、根拠が入力の前方にあるときに値を正確に取り出します。つまり
**何を入れるかと同じくらい、どの順で入れるかが精度を左右します。**

## 2. なぜ必要か

韓国語の公的機関報告書は表が多く、一つの文書の中に**よく似た表や数値が何度も**現れます。
予算書の年度別表、統計報告書の地域別表などです。

検索は関連するチャンクを複数返します。しかしその中で**答えを含むチャンクが先頭に来ない**と、
小規模モデルは前方に置かれた別の表の数値をそのまま答えに写します。答えは入力の中に
**あるのに**間違えるのです。このアダプタはその一点を狙います。

汎用のリランカーは**質問とどれだけ関連するか**を測ります。本アダプタはその上に、
**どのチャンクが実際に答えの根拠か**を人手で付けたラベルで追加学習しています。
両者は似て非なるものです。同じ話題を扱う複数のチャンクはすべて「関連あり」ですが、
答えを含むものは通常その中の一つだけだからです。

## 3. 何ではないか

| 該当しないもの | 説明 |
|---|---|
| 生成モデルではない | 答えを生成しません。チャンクの順序を変えるだけです |
| ゼロから学習したリランカーではない | 公開 BGE の本体は**凍結**し、LoRA アダプタのみ学習しました |
| 検索器ではない | 既存の候補を並べ替えるだけで、新たな文書は取得しません |
| 文脈圧縮器ではない | チャンクを削除・要約・書き換えしません |
| 汎用多言語モデルではない | 韓国語の公的機関報告書のみで学習しました |

## 4. 目的と適用範囲

**韓国語 PDF 文書を小規模言語モデルで扱えるようにすること**を目的に作りました。

### 4.1 向いている場面

| 場面 | 理由 |
|---|---|
| 韓国語の公的機関・政府報告書に対する質問応答 | 学習データと文書の性質が同じです |
| 表から値を探して答えるタスク | 学習データが表中心です |
| 小規模（数 B 規模）生成モデルを使う RAG | 根拠の位置の影響が特に大きい環境です |
| コンテキスト長に余裕がない環境 | 上位のいくつかだけを入れるとき、何を残すかが重要になります |

### 4.2 向いていない場面

| 場面 | 理由 |
|---|---|
| 英語など他言語の文書 | ベースが多言語のため動作はしますが、本アダプタは韓国語のみで学習しています |
| 表がほとんどない記述中心の文書 | 学習データが表中心です |
| 検索そのものの代替 | 候補に無いチャンクは順位を上げられません |
| チャンク内部の加工が必要なタスク | 本アダプタはチャンク本文を変更しません |

## 5. 導入と使い方

### 5.1 必要なもの

```bash
pip install torch transformers peft
```

| 項目 | 値 |
|---|---|
| `peft` | 学習時のバージョンは **0.20.0** です。これより古いと `adapter_config.json` の一部項目を読めない場合があります |
| デバイス | CPU でも動作します。GPU がある場合は `model.to("cuda")` を呼びます |
| ベースモデル | 初回実行時に `BAAI/bge-reranker-v2-m3` 約 2.2GB を取得します |

### 5.2 アダプタの結合

```python
import torch
from transformers import AutoTokenizer, AutoModelForSequenceClassification
from peft import PeftModel

BASE = "BAAI/bge-reranker-v2-m3"

tok = AutoTokenizer.from_pretrained(BASE)
model = AutoModelForSequenceClassification.from_pretrained(BASE)
model = PeftModel.from_pretrained(model, "./model")   # 本リポジトリの model/ を指す
model.eval()
```

### 5.3 スコア付けと並べ替え

```python
def rerank(question, chunks, batch_size=8, max_length=1024):
    # 質問とチャンク一覧を受け取り、スコアの高い順に返す
    scores = []
    for i in range(0, len(chunks), batch_size):
        part = chunks[i:i + batch_size]
        enc = tok([question] * len(part), part,
                  padding=True, truncation=True,
                  max_length=max_length, return_tensors="pt")
        enc = {k: v.to(model.device) for k, v in enc.items()}
        with torch.no_grad():
            scores.extend(model(**enc).logits.view(-1).float().tolist())
    order = sorted(range(len(chunks)), key=lambda i: -scores[i])
    return [(chunks[i], scores[i]) for i in order]
```

### 5.4 RAG パイプラインへの組み込み

```python
ranked = rerank(question, retrieved_chunks)
top_k  = [text for text, _ in ranked[:28]]
prompt = "質問: " + question + "\n\n根拠:\n" + "\n\n".join(top_k)
```

### 5.5 すでに BGE を使っている場合

**モデルを読み込んだあとに 1 行足すだけです。**

```python
model = AutoModelForSequenceClassification.from_pretrained(BASE)
model = PeftModel.from_pretrained(model, "./model")   # ← この行を追加

model = model.unload()      # アダプタを外すと元の公開モデルに戻る
```

### 5.6 使用時の注意

| 注意点 | 理由 |
|---|---|
| **バッチサイズを固定する** | バッチが変わると内部のパディング長が変わり、スコアがわずかに揺れることがあります。再現のため一つの値に固定します |
| **max_length は 1024** | 学習時の値です。大きく変えると学習時と条件が変わります |
| **質問とチャンクの順序** | トークナイザには `(質問, チャンク)` の順で渡します。逆にするとスコアが変わります |
| **スコアの意味** | 絶対値に意味はありません。**同一質問内での相対順位**のみを使います |
| **切り捨ては利用側が決める** | 本アダプタは並べ替えのみ行います。何件残すかはコンテキスト予算に合わせて決めます |
| **チャンクの境界** | 表は表単位、節は節単位で切ったチャンクで学習しています。文単位に細かく分けると学習時と異なります |

## 7. 評価 — Gemma 4 E2B で検証

### 7.1 測定条件

| 項目 | 値 |
|---|---|
| 生成モデル | `google/gemma-4-E2B-it`（実効 2.3B・GGUF Q8_0） |
| 実行環境 | `llama-server`・コンテキスト 10240・`temperature 0`・GPU 層 99・スレッド 4 |
| マシン | AWS g6.xlarge（NVIDIA L4） |
| 評価件数 | **81** |
| 変えたもの | **リランカーのみ。** 設問・候補チャンク・生成設定はすべて同一です |

評価設問は次の基準で選びました。リランカーなしの基本 RAG 入力で E2B が**誤答**し、かつ
その**誤った値が同じ入力に含まれる別のチャンク由来**である設問のみです。答えは入力の中に
あったのに、モデルが別のチャンクを読んだ場合です。この基準により、ベースラインは **0 / 81** です。

### 7.2 結果

| リランカー | 正答 | 回復率 |
|---|---|---|
| なし（基本 RAG） | 0 / 81 | 0.0% |
| 公開 `BAAI/bge-reranker-v2-m3` | 17 / 81 | 21.0% |
| **本アダプタ（DKU）** | **58 / 81** | **71.6%** |

公開モデルに対し **41 件（+50.6 ポイント）** 多く正答しました（McNemar 正確検定・両側 `p = 2.46e-10`）。

### 7.3 なぜ上がったか

正解根拠を**入力の 1 位**に置けた件数が分かれ目でした。

| リランカー | 正解根拠が 1 位の件数 |
|---|---|
| なし | 1 / 81 |
| 公開 BGE | 18 / 81 |
| **本アダプタ** | **79 / 81** |

同じ 81 件を二つに分けると原因がはっきりします。

| グループ | 件数 | 公開 BGE | 本アダプタ |
|---|---|---|---|
| 正解根拠の順位が**変わった**設問 | 61 | 6 / 61（10%） | **47 / 61（77%）** |
| 正解根拠の順位が**変わらなかった**設問 | 18 | 11 / 18（61%） | 11 / 18（61%） |

順位が変わらなかった設問では両モデルは**同一**です。つまり向上は設問が易しいからではなく、
**順位が変わったから**です。

### 7.4 確認できなかったこと

| 項目 | 状態 |
|---|---|
| 上位 28 件のみ残す選別 | この 81 件では**差を確認できませんでした**（`p = 1`） |
| 質問を根拠より前に置く配置 | この 81 件では**差を確認できませんでした**（`p = 1`） |
| 他の生成モデル | 検証していません。E2B のみで測定しました |
| 他言語・他の文書種別 | 検証していません |

確認できた効果は**リランカーの学習ひとつ**です。それ以外は本標本では方向を確認できませんでした。

## 8. 学習方法

| 項目 | 値 |
|---|---|
| ベースモデル | `BAAI/bge-reranker-v2-m3`（本体凍結） |
| 学習対象 | LoRA アダプタ — `r=8`・`alpha=16`・`dropout=0.05` |
| 対象モジュール | `key`・`query`・`value` |
| タスク種別 | `SEQ_CLS`（分類ヘッドも併せて保存） |
| 学習信号 | 人手で確認した**正解根拠ラベル** |
| 損失 | 正解根拠のスコアを上げる項＋正解根拠を非正解根拠より上位にする項（重み 1 : 1.0） |
| 学習件数 | 264（98 + 166） |
| epoch・学習率・seed | 5・0.0001・20260915 |
| max_length・step | 1024・980 |
| 所要時間 | 82.9 分（5.07 秒/step） |
| デバイス | NVIDIA L4（AWS g6.xlarge） |

### 8.1 どの epoch を採用するか — **学習前に規則として固定**

結果を見てから選ぶこと自体が選択バイアスになります。そこで規則を、学習を 1 step も回す前に
書き留めました。

```
1. 順位違反率が学習前（epoch 0）を上回る epoch は候補から除く
2. 残った中で正解根拠の分離指標が最も高い epoch を選ぶ
3. 同値の場合はより早い epoch を選ぶ
```

| 指標 | 学習前 | 採用 epoch 5 |
|---|---|---|
| 正解根拠がすべて非正解根拠より上位である設問の割合 | 0.4796 | **0.7959** |
| 順位違反率（低いほど良い） | 0.2866 | **0.1311** |

この 2 指標は**学習セット上の適合度**であり、下流タスクの性能ではありません。アダプタの選択に
のみ用いました。性能は 7 節で別途報告します。

## 10. 限界

| 限界 | 内容 |
|---|---|
| データ範囲 | 韓国 4 機関・44 文書から作成した 264 件で学習しました |

## 11. よくある質問

**ベースモデルも同梱していますか。** いいえ。`BAAI/bge-reranker-v2-m3` は公開リポジトリから
取得します。本リポジトリにはその上に載せるアダプタのみがあります。

**英語の文書に使えますか。** ベースが多言語なので動作はします。ただし本アダプタは韓国語のみで
学習しており、英語での効果は確認されていません。

**何件残すのがよいですか。** 評価では上位 28 件を使いました。ただしその選別自体の効果は
確認できていません（7.4）。コンテキスト予算に合わせて決めてください。

**スコアにしきい値を設けてよいですか。** 推奨しません。スコアの絶対値は質問ごとに分布が異なり、
しきい値がずれます。**同一質問内の相対順位**として使うのが安全です。

**公開されたファイルは論文で使用したものと同一ですか。** 同一です。バイト単位で一致します。
