# DKU-reranker-v1

**한국어** | [English](README.en.md) | [日本語](README.ja.md) | [中文](README.zh.md)

**한국어 PDF 문서를 다루는 검색증강생성(RAG)용 재순위 모델(reranker)이다.**
소형 언어모델(SLM)에 넣을 근거 조각의 순위를 바로잡아, 정답을 담은 조각이 입력의 맨 앞에 오게 한다.

공개 모델 [`BAAI/bge-reranker-v2-m3`](https://huggingface.co/BAAI/bge-reranker-v2-m3) 의
본체 가중치를 **동결**하고, 한국어 공공기관 PDF 보고서의 **정답 근거 라벨**로 LoRA 어댑터만 학습하였다.
어댑터 파일은 8.9MB이고, 기반 모델은 쓰는 쪽에서 공개 저장소에서 받는다.

| 항목 | 내용 |
|---|---|
| 쓰는 자리 | RAG 파이프라인의 **검색 뒤 · 생성 앞** |
| 하는 일 | 질문과 조각을 함께 채점해 **순위를 다시 매긴다** |
| 기반 모델 | `BAAI/bge-reranker-v2-m3` (본체 동결 · LoRA 어댑터만 학습) |
| 학습 자료 | 한국어 공공기관 PDF 보고서 264문항 · 네 기관 |
| 검증 | `google/gemma-4-E2B-it` 로 81문항 — 공개 BGE 17 대비 **58** |
| 크기 | 어댑터 8.9MB (`r=8`) |
| 라이선스 | Apache-2.0 |

`DKU` 는 단국대학교(Dankook University)를 가리킨다.

---

## 1. 무엇을 하는가

검색으로 가져온 조각(chunk)들 가운데 **정답의 근거가 되는 조각을 맨 앞으로 올린다.**

```
질문 + [조각1, 조각2, …, 조각N]
        ↓  각 (질문, 조각) 쌍에 점수 하나
        ↓  점수 내림차순으로 다시 정렬
질문 + [정답 근거, …, …]      ← 생성 모델에는 이 차례로 넣는다
```

소형 언어모델은 근거가 입력의 앞쪽에 있을 때 값을 정확히 뽑아낸다. 그래서 **무엇을 넣느냐만큼
어떤 차례로 넣느냐가 답의 정확도를 바꾼다.**

## 2. 왜 필요한가

한국어 공공기관 보고서는 표가 많고, 한 문서 안에 **비슷하게 생긴 표와 숫자가 여러 번** 나온다.
예산서의 연도별 표, 통계 보고서의 지역별 표가 그렇다.

검색은 관련 있는 조각을 여럿 가져온다. 그런데 그중 **정답을 담은 조각이 앞에 오지 않으면**,
소형 언어모델은 앞에 놓인 다른 표의 숫자를 답으로 옮겨 적는다. 답이 입력 안에 **있는데도**
틀리는 것이다. 이 어댑터는 그 지점 하나를 겨냥한다.

범용 재순위 모델은 **질문과 얼마나 관련 있는가**를 잰다. 이 어댑터는 그 위에
**어느 조각이 실제로 정답의 근거인가**를 사람이 표시한 라벨로 더 학습하였다.
둘은 비슷하지만 같지 않다 — 같은 주제를 다루는 조각 여럿이 모두 「관련 있음」인데,
그중 답이 든 것은 하나뿐인 경우가 많기 때문이다.

## 3. 무엇이 아닌가

| 아닌 것 | 설명 |
|---|---|
| 생성 모델이 아니다 | 답을 만들지 않는다. 조각의 차례만 바꾼다 |
| 처음부터 학습한 재순위 모델이 아니다 | 공개 BGE 본체는 **동결**했고 LoRA 어댑터만 학습하였다 |
| 검색기가 아니다 | 이미 검색된 후보의 순위만 바꾼다. 새 문서를 찾아오지 않는다 |
| 문맥 압축기가 아니다 | 조각을 지우거나 요약하거나 다시 쓰지 않는다 |
| 범용 다국어 모델이 아니다 | 한국어 공공기관 보고서로만 학습하였다 |

## 4. 목적과 쓰임새

**한국어 PDF 문서를 소형 언어모델에 적용하는 것**을 목표로 만들었다.

### 4.1 잘 맞는 자리

| 자리 | 왜 |
|---|---|
| 한국어 공공기관·정부기관 보고서 질의응답 | 학습 자료와 문서 성격이 같다 |
| 표에서 값을 찾아 답하는 과제 | 학습 자료가 표 중심이다 |
| 소형 언어모델(수 B 규모)을 쓰는 RAG | 근거 위치의 영향이 특히 크다 |
| 컨텍스트가 빠듯한 환경 | 상위 몇 개만 넣어야 할 때 무엇을 남길지가 중요해진다 |

### 4.2 맞지 않는 자리

| 자리 | 왜 |
|---|---|
| 영어 등 다른 언어 문서 | 기반 모델이 다국어라 동작은 하나, 이 어댑터는 한국어로만 학습하였다 |
| 표가 거의 없는 서술형 문서 | 학습 자료가 표 중심이다 |
| 검색 자체를 대신하려는 용도 | 후보에 없는 조각은 순위를 올릴 수 없다 |
| 조각 내부를 다듬어야 하는 과제 | 이 어댑터는 조각을 고치지 않는다 |

## 5. 설치와 사용

### 5.1 필요한 것

```bash
pip install torch transformers peft
```

| 항목 | 값 |
|---|---|
| `peft` | 학습에 쓴 판은 **0.20.0** 이다. 그보다 낮으면 `adapter_config.json` 의 일부 칸을 못 읽을 수 있다 |
| 장치 | CPU 에서도 돈다. GPU 가 있으면 `model.to("cuda")` 로 올린다 |
| 기반 모델 | 처음 실행할 때 `BAAI/bge-reranker-v2-m3` 약 2.2GB 를 내려받는다 |

### 5.2 어댑터 결합

```python
import torch
from transformers import AutoTokenizer, AutoModelForSequenceClassification
from peft import PeftModel

BASE = "BAAI/bge-reranker-v2-m3"

tok = AutoTokenizer.from_pretrained(BASE)
model = AutoModelForSequenceClassification.from_pretrained(BASE)
model = PeftModel.from_pretrained(model, "./model")   # 이 저장소의 model/ 을 가리킨다
model.eval()
```

### 5.3 점수 매기고 순위 바꾸기

```python
def rerank(question, chunks, batch_size=8, max_length=1024):
    # 질문과 조각 목록을 받아 점수가 높은 순으로 돌려준다.
    scores = []
    for i in range(0, len(chunks), batch_size):
        part = chunks[i:i + batch_size]
        enc = tok([question] * len(part), part,
                  padding=True, truncation=True,
                  max_length=max_length, return_tensors="pt")
        enc = {k: v.to(model.device) for k, v in enc.items()}
        with torch.no_grad():
            scores.extend(model(**enc).logits.view(-1).float().tolist())
    order = sorted(range(len(chunks)), key=lambda i: -scores[i])
    return [(chunks[i], scores[i]) for i in order]
```

### 5.4 RAG 파이프라인에 넣기

```python
# 아래 조각은 형태를 보이려는 예시다. 실제 보고서의 값이 아니다.
question = "○○ 사업의 2024년 집행률은 몇 퍼센트인가?"

chunks = [
    "Ⅰ. 사업 개요 … 추진 배경과 근거 법령 …",
    "Ⅱ. 예산 집행 현황 … 2024년 집행률 …",        # ← 정답 근거가 든 조각
    "Ⅲ. 향후 계획 … 연차별 추진 일정 …",
]

ranked = rerank(question, chunks)
for text, score in ranked:
    print(round(score, 4), text[:40])

top_k = [text for text, _ in ranked[:28]]          # 상위 k 개만 남긴다
prompt = "질문: " + question + "\n\n근거:\n" + "\n\n".join(top_k)
```

### 5.5 이미 BGE 를 쓰고 있다면

**모델을 불러온 뒤 한 줄만 더하면 된다.**

```python
model = AutoModelForSequenceClassification.from_pretrained(BASE)
model = PeftModel.from_pretrained(model, "./model")   # ← 이 줄만 추가

model = model.unload()      # 어댑터를 떼면 원래 공개 모델로 돌아간다
```

### 5.6 쓸 때 지킬 것

| 지킬 것 | 까닭 |
|---|---|
| **배치를 고정한다** | 배치가 달라지면 묶음 안의 패딩 길이가 달라져 점수가 미세하게 흔들릴 수 있다. 재현하려면 한 값으로 고정한다 |
| **최대 길이 1024** | 학습할 때 쓴 값이다. 크게 바꾸면 학습 때와 다른 조건이 된다 |
| **질문–조각 차례** | 토크나이저에 `(질문, 조각)` 차례로 넣는다. 뒤바꾸면 점수가 달라진다 |
| **점수의 뜻** | 절댓값에 의미를 두지 않는다. **같은 질문 안에서의 상대 순위**만 쓴다 |
| **자르는 것은 쓰는 쪽이 정한다** | 이 어댑터는 정렬만 한다. 몇 개를 남길지는 컨텍스트 예산에 맞춰 정한다 |
| **조각 경계** | 표는 표째로, 절은 절째로 자른 조각에서 학습하였다. 문장 단위로 잘게 자르면 학습 때와 달라진다 |

## 7. 검증 — Gemma 4 E2B 로 시험하였다

### 7.1 어떻게 측정하였나

| 항목 | 값 |
|---|---|
| 생성 모델 | `google/gemma-4-E2B-it` (유효 2.3B · GGUF Q8_0) |
| 실행기 | `llama-server` · 컨텍스트 10240 · `temperature 0` · GPU 층 99 · 스레드 4 |
| 기계 | AWS g6.xlarge (NVIDIA L4) |
| 평가 문항 | **81** |
| 바꾼 것 | **재순위 모델 하나뿐.** 문항·후보 조각·생성 설정은 모두 같다 |

평가 문항은 이렇게 골랐다. 재순위 없는 기본 RAG 입력에서 E2B 가 **틀렸고**, 그 **틀린 값이
입력에 함께 들어간 다른 조각에서 온** 문항만 모았다. 답은 입력 안에 있었는데 모델이 다른
조각을 읽은 경우다. 이 기준에 따라 기준선은 **0 / 81** 이다.

### 7.2 결과

| 재순위 | 맞은 문항 | 회복률 |
|---|---|---|
| 없음 (기본 RAG) | 0 / 81 | 0.0% |
| 공개 `BAAI/bge-reranker-v2-m3` | 17 / 81 | 21.0% |
| **이 어댑터 (DKU)** | **58 / 81** | **71.6%** |

공개 모델 대비 **41문항(+50.6%p)** 을 더 맞혔다 (McNemar 양측 정확검정 `p = 2.46e-10`).

### 7.3 왜 올랐는가

정답 근거를 **입력의 1순위**에 놓은 문항 수가 갈랐다.

| 재순위 | 정답 근거가 1순위인 문항 |
|---|---|
| 없음 | 1 / 81 |
| 공개 BGE | 18 / 81 |
| **이 어댑터** | **79 / 81** |

같은 81문항을 두 묶음으로 갈라 보면 원인이 분명해진다.

| 문항 묶음 | 문항 수 | 공개 BGE | 이 어댑터 |
|---|---|---|---|
| 정답 근거의 순위가 **바뀐** 문항 | 61 | 6 / 61 (10%) | **47 / 61 (77%)** |
| 정답 근거의 순위가 **그대로인** 문항 | 18 | 11 / 18 (61%) | 11 / 18 (61%) |

순위가 그대로인 문항에서는 두 모델이 **똑같다.** 즉 오른 것은 문항이 쉬워서가 아니라
**순위가 바뀌었기 때문**이다.

### 7.4 확인하지 못한 것

| 항목 | 상태 |
|---|---|
| 상위 28개만 남기는 선별 | 이 81문항에서 **차이를 확인하지 못했다** (`p = 1`) |
| 질문을 근거보다 앞에 두는 배치 | 이 81문항에서 **차이를 확인하지 못했다** (`p = 1`) |
| 다른 생성 모델 | 시험하지 않았다. E2B 하나로만 측정하였다 |
| 다른 언어·다른 문서 종류 | 시험하지 않았다 |

확인된 효과는 **재순위 모델 학습 하나**다. 나머지는 이 표본에서 방향을 확인하지 못했다.

## 8. 학습 방법

| 항목 | 값 |
|---|---|
| 기반 모델 | `BAAI/bge-reranker-v2-m3` (본체 동결) |
| 학습 대상 | LoRA 어댑터 — `r=8` · `alpha=16` · `dropout=0.05` |
| 대상 모듈 | `key` · `query` · `value` |
| 과업 유형 | `SEQ_CLS` (분류 머리를 함께 저장한다) |
| 학습 신호 | 사람이 확인한 **정답 근거 라벨** |
| 손실 | 정답 근거의 점수를 올리는 항 + 정답 근거가 비정답 근거보다 앞서게 하는 항 (가중 1 : 1.0) |
| 학습 문항 | 264 (D 98 · F 166) |
| epoch · 학습률 · seed | 5 · 0.0001 · 20260915 |
| 최대 길이 · step | 1024 · 980 |
| 소요 | 82.9분 (5.07초/step) |
| 장치 | NVIDIA L4 (AWS g6.xlarge) |

### 8.1 어느 epoch 을 쓸지 — **학습 전에 규칙으로 고정하였다**

결과를 보고 고르면 그 자체가 선택 편향이 된다. 그래서 규칙을 학습 한 step 전에 적어 두었다.

```
① 순서 위반율이 학습 전(epoch 0)을 넘는 epoch 은 후보에서 뺀다
② 남은 것 중 D 구제 지표가 가장 높은 epoch 을 고른다
③ 동률이면 더 이른 epoch 을 고른다
```

| 지표 | 학습 전 | 고른 epoch 5 |
|---|---|---|
| 정답 근거가 비정답 근거보다 모두 앞서는 문항 비율 | 0.4796 | **0.7959** |
| 순서 위반율 (낮을수록 좋다) | 0.2866 | **0.1311** |

이 두 지표는 **학습셋에서 측정한 적합도**이며 하류 과제의 성능이 아니다. 어댑터를 고르는 데만 썼다.
성능은 7절이 따로 보고한다.

| 평가 범위 | 생성 모델 하나(E2B) · 문항 81개에서만 확인하였다 |
| 평가 문항의 성격 | 기본 RAG 가 **틀린** 문항만 모은 집합이다. 일반적인 질문 분포가 아니다 |
| 겨냥한 실패 하나 | 「답이 입력에 있는데 다른 조각을 읽는」 경우만 다룬다. 검색이 못 가져온 경우는 고치지 못한다 |
| 비교 대상 | 공개 `bge-reranker-v2-m3` 하나와 견주었다. 다른 재순위 모델과는 견주지 않았다 |

## 11. 자주 묻는 것

**기반 모델도 함께 배포하나?** 아니다. `BAAI/bge-reranker-v2-m3` 는 공개 저장소에서 받는다.
이 저장소에는 그 위에 얹는 어댑터만 있다.

**영어 문서에 써도 되나?** 기반 모델이 다국어라 동작은 한다. 다만 이 어댑터는 한국어로만
학습했으므로 영어에서의 이득은 확인된 바 없다.

**몇 개를 남기는 게 좋은가?** 검증에서는 상위 28개를 썼다. 다만 그 선별 자체의 효과는
확인하지 못했다(7.4). 컨텍스트 예산에 맞춰 정하면 된다.

**점수에 임계값을 걸어도 되나?** 권하지 않는다. 점수의 절댓값은 질문마다 분포가 달라
임계값이 옮겨 간다. **같은 질문 안의 상대 순위**로 쓰는 것이 안전하다.

**공개한 파일이 논문에서 쓴 것과 같은가?** 같다. 바이트까지 동일하다.
